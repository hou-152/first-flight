# First Flight Step 0：需求钢人论证（Grill）

First Flight 的假设是：**写代码的瓶颈不是代码，是"用户到底想要什么"**。本 Step 0 把这个假设推到最前面——在写 BRIEF（长期纲领）之前，先用一次结构化的"双向钢人论证"，确认用户要解决的问题本身是成立的。

## 什么时候用

- 用户带着**模糊、未成型**的网站/产品想法来（"我想做个网站但不知道从哪开始"）
- 用户描述的"方案"可能是手段，不是目的（例：想做博客，但真正的问题是"想建立个人影响力"）
- 项目尚未启动、没有已有 spec 或代码

**不用**：用户已有明确 BRIEF/PRD；用户只问技术问题；迭代场景（已有 iterations/，只改 PRD）。

## 流程（一次对话，最多一轮追问）

在进入 first-flight-brief 之前，先执行：

1. **重述**：用最完整、最有力的方式，重述用户真正想解决的问题（不是复述需求，是把"问题"和"手段"分开）。
2. **双向钢人论证**：
   - 支持方：给出"用户当前想法是对的"的最强论证（找全所有支持理由）；
   - 反对方：给出"用户当前想法是错的/可以更好"的最强论证（包括不做的选项）。
3. **找分歧**：指出双方真正的分歧点，以及**最可能改变结论的关键变量**（通常是：目标用户是谁、成功标准是什么、有没有更轻的替代方案）。
4. **只问一个最关键的问题**：一次只问一个问题，等用户回答后再继续。禁止连问多个问题。

用户回答后，把结论整理成一页"问题定义"（不写文件，先在对话里展示）：

```markdown
## 问题定义（Step 0 产出）
- 真正要解决的问题：
- 为什么是现在/为什么是你：
- 最可能的替代方案：
- 本次建站要验证的关键假设：
- 不确定/留待 BRIEF 再定的：
```

用户确认后，带着这页定义进入 `first-flight-brief`。

## 与 grilling skill 的关系

本 skill 是 grilling 的**定向变体**：grilling 是通用盘问（任何计划/决策），本 skill 只做"建站前的问题定义"，且用钢人论证替代纯审问——**目的是帮用户看清，不是逼问**。若用户触发的是通用"grill 我"场景，用 grilling；若是建站启动，用本 skill。

## 注意

- **一次只问一个问题**。问多了是轰炸，用户会懵。
- **能查的事实不要问**（查文件、查环境）；只把"决策"交给用户。
- **不急着给判断**。4 步走完、用户回答关键问题后，才给出明确判断、理由和下一步。
- **允许结论是"别做网站"**。如果钢人论证表明用户真正的问题不需要网站，Step 0 的价值就是拦住一次错误启动——这是成功，不是失败。
- 本 skill 不写任何正式文档，产出只是对话中的"问题定义"页，供 BRIEF 引用。

## 对 first-flight 父 skill 的修改建议

父 skill 流程由 7 步改为 8 步：

```text
STEP 0 · 问题定义（钢人论证）  ← 新增，本 skill
  ↓  → first-flight-grill
STEP 1 · BRIEF.md              → first-flight-brief
STEP 2 · PRD.md                → first-flight-prd
...（其余不变）
```

父 skill 开场白在"检测 iterations/ + 展示流程简图"之后、询问交互/batch 模式**之前**，先问一次关键问题（钢人论证第 4 步）；batch 模式下改为在骨架中增加一节"问题定义"占位。
